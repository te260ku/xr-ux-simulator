# Missing Script Fix

## Problem

`PreviewLightTemplate` was generated in Edit Mode with a `PreviewLightView` component, but `PreviewLightView` was declared inside `PreviewPanel.cs` rather than in a same-named `PreviewLightView.cs` script asset.

For MonoBehaviour components persisted into a Unity scene, putting multiple MonoBehaviour classes in one `.cs` file makes the script asset/class association ambiguous. The generated component could therefore be restored as `Missing (Mono Script)` after serialization/reload, producing:

`The referenced script (Unknown) on this Behaviour is missing!`

## Fix

- Moved `PreviewLightView` to `PreviewLightView.cs` and added its `.meta` file.
- Applied the same correction to all other generated UI MonoBehaviour helper classes that were declared in a differently named `.cs` file:
  - `ColorKeyframeView`
  - `TimelineMiddleMousePanInput`
  - `TimelineWheelInput`
  - `PlayheadDragInput`
  - `TimelineRulerInput`
  - `TrackColorInput`
  - `TrackLabelClick`
  - `TimelineMarqueeSelectInput`
  - `PresetSwatchRightClick`
  - `HsvColorPickerControl`
  - `HsvHueRingInput`
  - `HsvSvSquareInput`
  - `ConsumePointerClick`
- Kept class names, namespaces and behavior unchanged; this is a script-asset layout refactor rather than a behavior change.
- Updated the Edit Mode UI generator and pre-Play repair pass so stale Missing MonoBehaviours from older generated scenes are removed and required components are repaired using the new valid script assets.

## Migration

After importing this version into an existing project, run:

`Tools > Lighting Scenario > Build Complete UI In Current Scene`

once in Edit Mode for an existing scene that was generated by an older version. This removes any already-serialized Missing component and regenerates `PreviewLightTemplate` with the valid `PreviewLightView` script reference.

Newly generated scenes do not use the old invalid script layout.

## Static checks performed

- All C# files have balanced braces, parentheses and brackets.
- All preprocessor blocks are balanced.
- No duplicate class declarations exist.
- No `MonoBehaviour` class under `Runtime/UI` remains in a `.cs` file whose filename differs from the class name.
- New `.meta` GUIDs are unique.

Unity Editor compilation and Play Mode execution cannot be run in this environment.
